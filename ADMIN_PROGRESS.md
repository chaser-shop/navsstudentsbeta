# ADMIN_PROGRESS.md — стан адмін-панелі Bob Smoke

**Оновлено:** 2026‑11‑12. **База:** архів `bobsmoke-redesign.zip` (окремий коміт «Import bobsmoke-redesign.zip baseline»). Аудит і план — у `ADMIN_AUDIT.md`.

## Підсумок
Адмін-панель завершено поверх наявного редизайну (не переписувалась з нуля): додано **Огляд** із реальними показниками й графіками, новий розділ **Аналітика**, **картку замовлення** (історія статусів, нотатки, зміна статусу з підтвердженням), **картку клієнта**, **керування категоріями** (назва, підпис, фото, націнка) і **лінійками** (фото, перейменування/перенесення, видалення), серверний пошук і фільтри замовлень і клієнтів. Інтерфейс повністю український. Бекенд змінено лише додаванням сумісних ендпоінтів і полів. Mini App не змінювався.

## Нові компоненти фронтенду
- `charts.js` — графіки на inline‑SVG без залежностей: часовий ряд (площа/стовпці, плавна монотонна крива, підказка на наведення й дотик), кільцева діаграма з легендою, горизонтальні й вертикальні смуги, спарклайн, бейдж зміни. Проєкт без збірки, тому React-бібліотеки (shadcn/ui, Magic UI, Framer Motion тощо) не підключались — їхні патерни (токени, мікроанімації, переходи) реалізовано нативно, іконки — у стилі Lucide.
- `shared.js` — статуси замовлень (назви, кольори, пілюлі), типи замовлень, тексти журналу дій, підписи дат.
- `ui.js` — менеджер шарів: стан `inert` і z-index шухляд тепер виводяться зі стека, додано `raiseLayer` (картку, відкриту з іншої картки, можна підняти наверх; Esc закриває верхню).
- Шухляди `#odrawer` (замовлення), `#cdrawer` (клієнт), `#kdrawer` (категорія); на телефоні — нижні листи.

## Бекенд (лише сумісні додавання)
| Ендпоінт | Зміна | Причина |
|---|---|---|
| `GET /api/stats/overview` | новий, лише читання | огляд: виручка, ряди за 30 днів, статуси, клієнти, товари, чати, останні замовлення, журнал дій |
| `GET /api/stats/analytics?date_from&date_to` | новий, лише читання | аналітика за період із попереднім періодом для порівняння (до 366 днів) |
| `GET /api/users/{tg_id}` | новий | картка клієнта |
| `GET /api/users` | фільтр у запиті MongoDB, ключі `total`, `matched` | виправлено B4: пошук відбувався після `limit`. Пошук за ID тепер лише за точним ID |
| `GET /api/orders` | параметри `q`, `tg_id`, `order_type`; ключі `page`, `pages` | серверний пошук і фільтри (B1, F8) |
| `GET /api/chats/{id}` | останні 500 повідомлень у хронологічному порядку | виправлено B5 |
| `GET /api/categories` | ключі `title`, `sub` (типові назва й підпис із `catalog.CATEGORY_META`) | картки категорій показують те, що бачить покупець |
| `ensure_indexes` | `orders.created_at`, `users.registered_at` | діапазонні запити статистики |

Правила підрахунку: **виручка** — сума `total` замовлень, крім «Відхилене»/«Скасоване»; «Виконано на» — лише «Виконане»; **прибуток** — лише відомі значення (позиції без закупівельної ціни не вигадуються); **дні** — за `Europe/Kyiv`; сума товару в топі — за цінами позицій до знижки на замовлення. Усі нові ендпоінти захищені `current_admin` (JWT), є тест на 401.

## Відомі обмеження
1. Категорії — фіксований набір із 4 (див. `ADMIN_AUDIT.md` §4); створення/видалення потребує змін бізнес-логіки й Mini App.
2. Статистика рахується в Python за запитом із проєкціями й індексом за датою — достатньо для тисяч замовлень; для сотень тисяч варто перейти на агрегаційні конвеєри MongoDB і кешування.
3. Видалення цілої лінійки доступне лише для рідин (так працює наявний ендпоінт).
4. Поточні ризики з `PROJECT_AUDIT.md` (compliance‑гейт, `MINIAPP_DEV_MODE`, ідемпотентність замовлень, переходи статусів тощо) свідомо не змінювались.

## Як продовжити
1. `docker compose up -d mongo`; `.env` з `MONGODB_URI=mongodb://127.0.0.1:27017`, `JWT_SECRET` (≥32 символи), `MINIAPP_DEV_MODE=1` (лише локально), `REQUIRED_CHANNEL=off`, `USER_SYNC_HOURS=0`, `KEEPALIVE_SECONDS=0`.
2. `python -m backend.cli create-admin`, `python -m backend.cli import-products --apply`.
3. `uvicorn backend.main:app --port 8000` → http://127.0.0.1:8000/admin/ і http://127.0.0.1:8000/app/.
4. `pytest` (конфіг у `pytest.ini`).
5. Код нових розділів — у модулях `frontend/admin/js/*.js`; спільний контекст (`ctx` в `admin.js`) дає мережу (`api`), переходи (`goOrders`, `goProducts`, `goUsers`) і відкриття шухляд (`openOrder`, `openCustomer`, `openChat`).
