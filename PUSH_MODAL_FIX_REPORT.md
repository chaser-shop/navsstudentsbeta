# PUSH_MODAL_FIX_REPORT

Дата: 2026-11-16. Проєкт: НАВС Електронний щоденник (`chaser-shop/navsstudentsbeta`).

## Причина проблеми

Модальне вікно Web Push `#pushAsk` («Сповіщення вимкнені» / «Увімкнути сповіщення?»)
з'являється асинхронно після завершення `sync()` у застосунку (`maybeAskPush()`,
`public/app.js`). Воно блокує pointer-події по сайдбару та subnav, тому Playwright-тести
отримували:

- `#pushAsk intercepts pointer events`
- `TimeoutError: page.click` (кліки по `.sb-item`, `.sb-user`, `.subnav button`)

Причини, які спричиняли падіння:

1. `dismissPushAsk` перевіряв наявність кнопки **разу** (без очікування), а вікно з'являється
   за ~1 tick після sync() — тобто на момент перевірки його ще не було, і наступний клік
   блокувався.
2. Тести очікували `.sb-user` (видимість сайдбару), але на **мобільних** viewport'ах сайдбар
   прихований (`display:none`, навігація — нижній `tabbar`), тому `.sb-user` ніколи не видимий.
3. `openApp()` встановлював токен, але пристрій сесії (X-Device-Id) не збігався з тим, за яким
   підписано токен → сервер відповідав 401 і витирав токен.
4. Спільний сервер між 7 viewport-проєктами вичерпував RateLimit (429 «Забагато спроб»).

## Що саме виправлено

1. **`dismissPushAsk`** тепер очікує `#pushAsk` у стані `visible` (з timeout), потім
   натискає реальну кнопку `data-act="pushLater"` («Зрозуміло»/«Не зараз») і чекає `detached`.
   Без `force: true`. Не вмикає сповіщення — лише ховає запрошення до наступного заходу
   (оригінальна поведінка `pushLater`, `askDismissed=true`).
2. **`openApp`** встановлює `token`/`deviceId` через `JSON.stringify` (застосунок читає їх
   через `LS.get` = `JSON.parse`) та передає правильний `X-Device-Id`, щоб сесія не скидалась.
   Автоматично викликає `dismissPushAsk` перед поверненням.
3. **Вмісна навігація** (`isMobileViewport` + `expectAuthenticated` + `navigateTab`):
   на десктопці — сайдбар `.sb-item`; на мобільному — нижній `tabbar` `.tab` + subnav.
   Це усунуло падіння S3/S4/S5/A1/M3 на мобільних viewport'ах.
4. **RateLimit** не блокує легітимні тести на спільному сервері.

## Збережена функціональність сповіщень

- `#pushAsk` **не видалено**, Web Push **не вимкнено**.
- Логіка `maybeAskPush` / `enablePush` / `pushAllow` / `pushLater` / `pushOn` у `public/app.js`
  не змінювалась — реальні користувачі бачать те саме запрошення та кнопки.
- Тести лише натискають офіційну кнопку `pushLater`, імітуючи дійсну дію користувача.

## Залишені питання / зауваження

- `public/app.js` (`loadNavsGroups`): виправлено, щоб список груп на сторінці входу оновлювався
  після завантаження. Якщо потім користувач вводить логін/пароль, оновлення `<select>`
  виконується на місці (без ре-рендеру), тож введене не стирається.
- Мобільна навігація в тестах використовує нижній `tabbar`. Якщо зміниться структура `tabbar`
  або з'явиться hamburger-меню для сайдбару на мобільному, `navigateTab`/`expectAuthenticated`
  доведеться оновити.
- `RATE_LIMIT_MAX` підвищено **лише в тестовому** сервері (`test/pw-server.js`). Production
  поведінка (30 запитів/10 хв на IP) збережено.
