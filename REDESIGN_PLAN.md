# REDESIGN_PLAN.md — дорожня карта редизайну Bob Smoke

Базується на `PROJECT_AUDIT.md`. Мета — повністю нова візуальна система та UX для Mini App і адмін‑панелі **без зміни контракту API, бізнес‑логіки, MongoDB, авторизації та інтеграцій**. Мова всього інтерфейсу — українська.

## 0. Ключові архітектурні рішення

| Рішення | Обґрунтування |
|---|---|
| **Zero‑build** (vanilla CSS + ES‑modules, без npm) | Render збирає проєкт лише через `pip install`; FastAPI віддає `frontend/*` як статику; жодних нових залежностей і змін деплою. Усі «бібліотечні» патерни (shadcn‑токени, Magic UI‑мікроанімації, Framer‑подібні переходи) реалізуються нативно: CSS custom properties, `color-mix()`, `scroll-snap`, View Transitions API (прогресивно), Web Animations API, `IntersectionObserver`. |
| Прибрати three.js, Material Symbols, Inter Tight, Anton | −~170 КБ JS, −іконковий шрифт (ризик англійських лігатур), менше блокуючих запитів. Єдиний набір inline‑SVG іконок (lucide‑стиль). |
| Шрифти: **Inter** (текст) + **Manrope** (заголовки, ціни) з `display=swap` | Обидва мають повну кирилицю; Manrope дає сучасний геометричний характер без «кричущості» Unbounded. |
| Зберегти hash‑роутинг, `localStorage['miniapp_state_v2']`, усі `data-*` дії та payload’и | Немає SPA‑fallback на бекенді; збережені кошики користувачів не губляться. |
| Єдиний аватар — `img/logo.png` (лаймове кільце) | Відповідає палітрі; `logo.jpg` (жовте кільце) більше не використовується. |
| Бекенд — лише мікроправки | `database.py` (TLS, виконано), типова назва «Bob Smoke», підпис «Под‑системи», `pytest.ini`. Жодних змін схем, роутів, логіки. |

## 1. Дизайн‑система «Bob Smoke UI»

**Палітра (незмінна брендова основа):** фон `#06070a` / `#0a0a0c`; текст `#f3f4ee`; приглушений `#8b8f84`; акцент лайм `#c6ff3d` (hover `#d6ff62`, чорнило на акценті `#172000`); небезпека `#ff6b6b`; попередження `#ffb020`; «вогонь» `#ff5a1f`. Поверхні — напівпрозорі білі шари `rgba(255,255,255,.04/.07/.11)` з лініями `rgba(255,255,255,.09)`; акцентні підсвітки `rgba(198,255,61,.12/.35)`.

**Токени:** радіуси 8/12/16/22/28/pill; відступи 4‑32; тіні `0 20px 50px -20px rgba(0,0,0,.6)`, лаймове сяйво для primary; easing `cubic-bezier(.2,.8,.2,1)` і spring `cubic-bezier(.34,1.56,.64,1)`; тривалості 160/240/360 мс; `prefers-reduced-motion` вимикає анімації.

**Компоненти (спільні для обох застосунків):** `.btn` (primary/secondary/ghost/danger/icon), `.chip`, `.seg`, `.pill` (статуси), `.badge`, `.fld/.inp` (поле з підписом, помилкою, підказкою), `.card` (товар), `.tile` (категорія), `.list/.li`, `.kv`, `.sum` + `.progress` (прогрес до знижки), `.step` (степер), `.sheet` (нижній лист), `.dialog` (підтвердження/введення), `.toast`, `.skeleton`, `.empty`, `.tabbar` (нижня навігація), `.topbar`, `.avatar`.

## 2. Фази реалізації

### Фаза A — Фундамент Mini App
- **Завдання:** новий `index.html` (мета, шрифти, кореневі контейнери, `theme-color #06070a`), новий `css/styles.css` з нуля (токени → базові стилі → компоненти → екрани → гейти → адаптив/safe‑area/клавіатура → reduced‑motion), набір іконок у `app.js`.
- **Файли:** `frontend/miniapp/index.html`, `frontend/miniapp/css/styles.css`, `frontend/miniapp/js/app.js` (секція іконок/утиліт).
- **Очікуваний результат:** застосунок завантажується без three.js/іконкового шрифту, усі токени доступні.
- **Залежності:** немає. **Ризики:** поламані класи, на які спирається логіка (`.hide`, `#view`, `#bar`, `#tabs`, `#toast`, `#modegate`, `#subgate`) — зберігаються.

### Фаза B — Екрани Mini App (`frontend/miniapp/js/app.js`, `data.js` — мінімально)
1. **Гейт входу** (вибір опт/роздріб + 18+): компактний екран з аватаром, двома картками‑радіо, юридичним текстом, однією CTA; без маркетингових вигадок.
2. **Головна:** topbar (аватар, назва, режим, кошик), hero‑картка з аватаром і CTA, плитки категорій (2 колонки, з фото з налаштувань), «Гаряче зараз» (горизонтальний snap‑скрол), «Наш вибір», «Вам може сподобатись», інформаційна смуга (доставка, мінімум, графік). Секції «Новинки/Хіти» рендеряться лише за наявності даних.
3. **Каталог / Категорія:** пошук у хедері, плитки категорій, грид товарів; липкі фільтри (сегмент сортування «Популярні / Дешевші / Дорожчі», чіпи брендів); порожній стан зі скиданням.
4. **Товар:** медіа з безпечним `aspect-ratio`, бейджі, вибір варіанта/міцності чіпами, ціна, опис, характеристики; липка нижня панель (додати / степер / стан недоступності).
5. **Пошук:** поле з очищенням, підказки (бренди, категорії), лічильник результатів, дебаунс 120 мс.
6. **Кошик:** рядки з мініатюрою, степером, видаленням; картка підсумку з прогрес‑баром до наступного рівня знижки, рядками знижок, мінімумом; CTA.
7. **Оформлення:** крокові секції «Контакти → Доставка (місто, відділення) → Промокод → Оплата → Підсумок», інлайн‑валідація, стани завантаження/порожнього пошуку НП, липка кнопка підтвердження, екран успіху.
8. **Профіль:** картка користувача з режимом, меню; замовлення (список зі статус‑пілюлями, деталі з таймлайном статусу), обране, запрошення друга (картка посилання, лічильники, персональні коди), особисті дані, допомога (акордеон FAQ), про магазин.
9. **Системні стани:** скелетони завантаження, порожні стани з ілюстраціями, помилки з повтором, тост, гейт підписки, помилка завантаження каталогу, «не знайдено».
- **Очікуваний результат:** усі маршрути та `data-*` дії працюють як раніше, payload’и API незмінні.
- **Ризики:** регресія оформлення (НП, промокод) — перевірити вручну через API‑стаби; продуктивність гриду (79 груп) — `content-visibility:auto`.

### Фаза C — Адмін‑панель (`frontend/admin/index.html`, `css/admin.css`, `js/admin.js`)
- **Статус (2026‑11‑12):** виконано й перевірено в браузері; додатково — огляд з реальною статистикою, розділ «Аналітика», картки замовлення й клієнта, керування категоріями та лінійками. Деталі — `ADMIN_AUDIT.md`, `ADMIN_PROGRESS.md`.
- **Завдання:** app‑shell із бічною навігацією (≥1024 px) і нижньою панеллю (мобільні), розділ **«Огляд»** (активні замовлення, непрочитані чати, користувачі/кошики, реферали, стан розсилки — з наявних ендпоінтів), редизайн усіх розділів: товари (таблиця → адаптивні рядки, фільтри, drawer редактора), лінійки/ціни, замовлення (картки зі статус‑пілюлями, фільтри, дії), чати (двопанельний інбокс), користувачі, реферали, розсилки, налаштування (групи), Excel‑синк; заміна `confirm()/prompt()` на `.dialog` (Promise‑API); тост; усунення англійських рядків; виправлення накопичення інтервалів; мобільні таблиці.
